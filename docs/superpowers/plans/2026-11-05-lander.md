# Pacer Landing Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the public Pacer landing page in `lander/`: a dark guilloche-track hero with the live bot conversation, then How it works, the real ₦20,000 comparison, Safety, tickers, the Nigeria band, FAQ and a final CTA.

**Architecture:** A Next.js 16 App Router page rendered almost entirely as static Server Components. One deterministic generator (`lib/guilloche.ts`) draws every engraving as static SVG on the server. A handful of small client islands add behaviour; Motion for React is used only in the hero sequence and chat. All copy and data live in `content/`.

**Tech Stack:** Next.js 16.4.5 (App Router, `cacheComponents` on), React 19.3, TypeScript strict, Tailwind CSS 4 (existing turbopack loader), `motion` (LazyMotion + domAnimation), `next/font/google`, `next/og`, Vitest 5 (node environment, `react-dom/server` for markup tests). Bun installs, Node runs.

**Spec:** `docs/superpowers/specs/2026-11-05-lander-design.md` (read it before any task; section numbers below refer to it).

## Review Focus

1. **No JavaScript or slow hydration:** every section's content must be visible and every CTA must work from the server HTML; scroll-reveal hiding applies only after the observer has armed (pinned in Task 7).
2. **Reduced motion and the pace dot:** the dot must rest on the start line unless an island explicitly starts it, so neither a no-JS load nor a reduced-motion user sees it move (pinned in Task 4).
3. **Chart scrubbing at the edges:** pointer positions left of, right of, or outside the chart, and Home/End/arrow keys at the first and last month, must clamp to Oct 2021…Oct 2026, never produce `undefined` rows (pinned in Task 8).
4. **Anchor links under the sticky nav:** following `#how`, `#safety` or `#faq` must not hide the section heading under the frosted bar (pinned in Task 5).
5. **360 px phones:** the hero headline, the result rows' large figures and the ticker chips must not overflow or force sideways scroll (pinned in Task 11's visual pass, with a CSS-level check in Task 6).

### Task 3: The guilloche generator

**Files:**
- Create: `lander/lib/guilloche.ts`
- Test: `lander/test/guilloche.test.ts`

**Interfaces:**
- Produces:
  - `type Loop = { cx: number; cy: number; width: number; height: number; radius: number }` — a rounded rectangle centred at `(cx, cy)`; a stadium when `radius === height / 2`.
  - `loopPoint(loop: Loop, t: number, offset: number): { x: number; y: number }` — `t ∈ [0, 1)` is the fraction of perimeter, measured clockwise from the top-left end of the top straight; `offset` moves outward along the normal (negative = inward).
  - `offsetLoopPath(loop: Loop, offset: number): string` — exact closed path using `A` arcs.
  - `strandPath(loop: Loop, o: { center: number; amplitude: number; waves: number; phase: number }): string` — closed path of a sine strand along the loop; one relative quadratic `q` segment per half-wave (zero crossing to zero crossing, control point at twice the amplitude), coordinates to 1 decimal.
  - `rosettePath(o: { cx: number; cy: number; radius: number; petals: number; amplitude: number; phase: number }): string` — closed polar sine curve, same curve encoding.
  - `engrave(loop: Loop, o: { lanes: number; laneWidth: number; strandsPerLane: number; waveLength: number; infieldLines: number; startT: number }): Engraving` where `type Engraving = { laneLines: string[]; strands: string[] /* one combined path per lane */; infield: string[]; dotPath: string /* centre of lane 1 */; start: { x: number; y: number }; startLine: { x1: number; y1: number; x2: number; y2: number }; laneNumbers: { x: number; y: number; label: string }[] }`.
- Defaults later tasks use: `strandsPerLane: 4`, `waveLength: 36`, `infieldLines: 6`, `startT: 0.08`.

- [ ] **Step 3: Implement `lib/guilloche.ts`**

Perimeter `P = 2(width − 2r) + 2(height − 2r) + 2πr`, walked as top straight → top-right quarter arc → right straight → … → top-left quarter arc. A strand's `waves` is `round(P_center / waveLength)` when called from `engrave`, so it always closes. For a half-wave from `t0` to `t1`: the end point is the zero crossing at `t1`; the control point is the base point at the middle `t` offset by `center ± 2·amplitude` (sign alternates). Lane `i` (0-based) spans offsets `[i·laneWidth, (i+1)·laneWidth]`; strands sit at `center = i·laneWidth + laneWidth/2`, `amplitude = 0.4·laneWidth`, `phase = j·2π/strandsPerLane`, lane `i` uses `waves + 2i`. Infield lines at offsets `−14k` for `k = 1..infieldLines`. Start line and lane numbers at `startT` (numbers 14 px before the line along the lane centre).
